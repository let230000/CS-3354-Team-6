# 4.1 Use cases selected for analysis

| Use case | Name | Why it was selected | Non-trivial steps |
|---|---|---|---|
| UC-03 | Reserve and Pay for a Listing | Specified in full at P1. It carries most of the product, it is the only use case that involves the Payment Processor, and it is the one we are least sure we can build (R2). It touches the most quality requirements (QR-03, QR-05) and has a failure the Buyer can see (declined payment). | (2), (4), (6) |
| UC-04 | Confirm Handoff | Specified in full at P1. It is the only way a listing becomes Sold (FR-07), and it needs both the Seller and the Buyer to confirm, which is easy to get wrong. | (0), (4) |
| UC-01 | Post a Listing | Every trade starts with a listing, and QR-02 depends on it. Expanding it showed that FR-02 and the Listing definition in 1.3 disagree about which items a listing has. | (0), (4), (6) |
