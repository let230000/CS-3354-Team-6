# 4.2 Expanded use cases

Author: Steven Law (Analyst + Designer). Section 4.2 of the P2 document, BookBridge, CS 3354 Team 6.

## UC-03 Reserve and Pay for a Listing

| Field | Content |
|---|---|
| **Primary actor** | Buyer |
| **Supporting actors and external systems** | Payment Processor (external system that takes the payment, so card details never reach BookBridge; CON-02) |
| **TUCBW (this use case begins when)** | The Buyer asks to reserve an Available listing they found in search (UC-02). |
| **TUCEW (this use case ends when)** | The Buyer sees that the listing is Reserved for them, with the price paid and the Seller’s UTD email address to arrange the handoff. |
| **Preconditions** | The Buyer is signed in through UTD NetID (FR-01, CON-01). The Buyer has opened a listing from the search results (UC-02). |
| **Postconditions** | The listing is Reserved, linked to this Buyer and no longer appears in buyer search results (FR-10). The Payment Processor holds a record of the completed payment. A reservation notice is waiting for the Seller (FR-09). BookBridge has stored no card details (QR-03). |
| **Traces to requirements** | FR-01, FR-06, FR-08, FR-09, FR-10; QR-03, QR-04, QR-05; CON-01, CON-02 |

| Actor input / action | System response |
|---|---|
|  | (0) The system shows the listing the Buyer opened: course, title, edition, ISBN, condition, price, the Seller’s name and the listing status (Available). |
| (1) The Buyer asks to reserve the listing. | (2) The system holds the listing for the Buyer and shows the price to pay, the time left on the 10-minute hold, and a request to go ahead with payment. |
| (3) The Buyer agrees to pay. | (4) The system passes the Buyer to the Payment Processor with the amount due. |
| (5) The Buyer gives their payment details to the Payment Processor. | (6) The system shows the Buyer that the listing is now Reserved for them, with the title, the price paid, the Seller’s name and the Seller’s UTD email address to arrange the handoff. |
| (7) The Buyer reads the reservation confirmation. |  |

| Alternate flow | At step | Condition | What happens | Ends or rejoins at |
|---|---|---|---|---|
| A1 | (1) | The listing belongs to the Buyer. | The system tells the Buyer they cannot reserve their own listing. | Ends. |
| A2 | (2) | Another Buyer has already held or reserved the listing (QR-05). | The system tells the Buyer the listing is no longer available and shows the search results again. | Ends. |
| A3 | (3) | The Buyer decides not to pay. | The system releases the hold and shows the listing as Available again. | Ends. |
| A4 | (5) | The Buyer does not finish paying within 10 minutes (FR-08). | The system releases the hold and the listing returns to Available. When the Buyer comes back, the system tells them the hold ended and the listing was not reserved. | Ends. |
| A5 | (5) | The Payment Processor declines the payment. | The system tells the Buyer the payment was declined, keeps the hold for the time left, and asks them to try another payment method. | Rejoins at (3). |
| A6 | (5) | The Payment Processor does not report a result. | The system tells the Buyer the payment could not be confirmed and the listing is not reserved yet. The hold stays until it ends (A4). | Ends. |

## UC-04 Confirm Handoff

| Field | Content |
|---|---|
| **Primary actor** | Seller |
| **Supporting actors and external systems** | None. The Buyer confirms receipt separately in UC-07 Confirm Receipt. |
| **TUCBW (this use case begins when)** | The Seller reports that the book for one of their Reserved listings has been handed to the Buyer. |
| **TUCEW (this use case ends when)** | The Seller sees their handoff confirmation recorded and the listing shown as waiting for the Buyer to confirm receipt. This use case continues with UC-07 Confirm Receipt (Buyer), which closes the trade. |
| **Preconditions** | The Seller is signed in through UTD NetID (FR-01, CON-01). |
| **Postconditions** | The Seller’s confirmation is recorded against the listing with its time. The listing stays Reserved until the Buyer confirms receipt (UC-07), and then becomes Sold (FR-07). |
| **Traces to requirements** | FR-01, FR-07; QR-04; CON-01 |

| Actor input / action | System response |
|---|---|
|  | (0) The system shows the Seller’s listings with the status of each. Each Reserved listing also shows the Buyer’s name, the date it was reserved and whether the Buyer has confirmed receipt. |
| (1) The Seller reports that the book for one Reserved listing has been handed over. | (2) The system shows the listing’s title, the Buyer’s name and the price paid, and asks the Seller to confirm that the book changed hands. |
| (3) The Seller confirms. | (4) The system shows that the Seller’s confirmation is recorded with its time, and that the listing stays Reserved until the Buyer confirms receipt. |
| (5) The Seller sees the confirmation. |  |

| Alternate flow | At step | Condition | What happens | Ends or rejoins at |
|---|---|---|---|---|
| A1 | (0) | The Seller has no Reserved listings. | The system shows that there is no handoff to confirm. | Ends. |
| A2 | (3) | The Seller says the book has not changed hands yet. | The system records nothing and the listing stays Reserved. | Ends. |
| A3 | (3) | The Seller reports that the Buyer did not come to the handoff. | The system keeps the listing Reserved and directs the Seller to dispute handling outside BookBridge (out of scope, 1.2). | Ends. |
| A4 | (4) | The Buyer has already confirmed receipt (UC-07). | The system marks the listing Sold, removes it from search results, and shows the Seller that the trade is complete (FR-07). | Ends. |

## UC-01 Post a Listing

| Field | Content |
|---|---|
| **Primary actor** | Seller |
| **Supporting actors and external systems** | None |
| **TUCBW (this use case begins when)** | The Seller asks to post a new textbook listing. |
| **TUCEW (this use case ends when)** | The Seller sees the new listing in their listings with the status Available. |
| **Preconditions** | The Seller is signed in through UTD NetID (FR-01, CON-01). |
| **Postconditions** | A listing with the course, title, edition, ISBN, condition and price is recorded under this Seller with the status Available, and it appears in buyer search results (FR-04, FR-10). |
| **Traces to requirements** | FR-01, FR-02, FR-04, FR-10; QR-02, QR-04; CON-01 |

| Actor input / action | System response |
|---|---|
|  | (0) The system shows the Seller’s listings, each with its title, price and status, and offers to post a new listing. If the Seller has no listings, it says so. |
| (1) The Seller asks to post a new listing. | (2) The system asks for the course, title, edition, ISBN, condition and price, and shows the condition grades a listing can have. |
| (3) The Seller enters the course, title, edition, ISBN, condition and price. | (4) The system shows the listing as Buyers will see it and asks the Seller to confirm. |
| (5) The Seller confirms. | (6) The system shows the new listing in the Seller’s listings with the status Available. |
| (7) The Seller sees the new listing. |  |

| Alternate flow | At step | Condition | What happens | Ends or rejoins at |
|---|---|---|---|---|
| A1 | (3) | A required item is missing, or the price is not an amount greater than zero. | The system names the item to fix and keeps everything else the Seller entered (FR-02). | Rejoins at (3). |
| A2 | (3) | The ISBN is not a valid 10- or 13-digit ISBN. | The system says the ISBN is not valid and asks the Seller to check it. | Rejoins at (3). |
| A3 | (5) | The Seller decides not to post. | The system posts nothing and shows the Seller’s listings unchanged. | Ends. |
